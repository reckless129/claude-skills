# 一分钟故事圣经 (One-Minute Story Bible)

## Overview

用一套**逐阶段确认**的流程,把"小猫旅居"的一分钟故事从立项做到可交付的分镜和 Seedance 2.0 提示词。

**核心原则:一条消息只推进一个阶段;没有用户明确确认,不进入下一阶段。**

这不是形式主义。跳过确认点会导致三个具体后果:agent 自己发明世界观、镜头数失控、用户在没同意的前提下被锁进一个故事。

## When to Use

- 用户要为芋仔的小猫旅居 vlog 写新一集
- 用户要故事大纲、剧本、剧情节拍、分镜
- 用户要为分镜生成 Seedance 2.0 提示词
- 用户要修改某一集的节拍、分镜或提示词

不适用:长片、非宠物题材、单张图片生成、纯剪辑操作。

## 开工前必读

1. `references/story-bible.md` — 芋仔的世界观、性格、声音、硬约束
2. `references/story-types.md` — 五种故事类型与各自的节拍模板
3. `references/templates.md` — 每个阶段的输出模板
4. `references/visual-style.md` — 参考图的视觉风格与三层提示词锚点

其余参考按阶段读取。

## 阶段地图

| 阶段 | 名称 | 产出 | 确认问题 |
|---|---|---|---|
| 0 | 立项卡 | 故事类型、目的地、时长、情绪核心、观众带走的一句话 | 这个立项对吗? |
| 1 | 故事脊柱 | logline、欲望、阻碍、转折、结尾画面 | 这条脊柱立得住吗? |
| 2 | 节拍大纲 | 按故事类型的节拍表,含时长与情绪变化 | 节拍顺序和情绪曲线对吗? |
| 3 | 完整剧本 | 交付级剧本:场景、时长、画面、台词、声音、连续性 | 剧本可以定稿吗? |
| 4 | 分场剧情节拍 | 每场戏拆成 2–4 个节拍,标明变化 | 每场戏的节拍对吗? |
| 5 | 分镜表 | ≤9 镜,含景别、运镜、画面、台词、声音、制作方式 | 分镜可以进入提示词吗? |
| 6 | Seedance 2.0 提示词 | 每镜一条结构化提示词 + 参考图映射 + 负面约束 | 提示词可以交付吗? |
| 7 | 交付质检 | 按清单逐项检查,输出交付包 | 最终确认 |

## 节点确认协议(硬约束)

每个阶段结束时,只输出本阶段内容,然后以下面这个格式收尾:

```
【阶段 N · 等待确认】
本阶段产出:{一句话}
请你确认:
1. {需要用户拍板的具体点}
2. {需要用户拍板的第二个点}
回复「确认」进入阶段 N+1;要改就直接说修改点。
```

规则:
- **不在同一条消息里输出下一阶段的内容**,哪怕只是一段草案。
- 用户说「确认」「可以」「继续」才算确认;沉默、点赞、换个话题都不算。
- 用户说「你定」:替用户做选择,但在输出里标 `[我的选择]` 和理由,然后仍然停在确认点。
- 用户说「直接给完整方案」:回答「可以,我按流程逐阶段推进;先把阶段 0 确认掉」,然后只输出阶段 0。
- 上一集的确认不覆盖这一集;每一集都从头走。

## 阶段执行要点

### 阶段 0 · 立项卡

用 `references/templates.md` 的立项卡。先读 `references/story-bible.md`。故事类型从 `references/story-types.md` 里选 A–E;用户没主意时,你按素材推荐一个并说明理由。只问会改变故事的问题,不要一次问十个。

### 阶段 1 · 故事脊柱

一句话 logline + 主角想要什么 + 阻碍 + 转折 + 结尾画面 + 观众带走的一句话。结尾画面必须是一个可拍的画面,不是道理。

### 阶段 2 · 节拍大纲

按选定的故事类型套节拍模板。每个节拍标明:时长、发生什么、情绪/信息发生了什么变化。总时长控制在 50–65 秒。没有变化的节拍删掉。

### 阶段 3 · 完整剧本

按 `references/script-standard.md`。每个场景必须有:场景号、地点、时间、时长、出场、画面动作、台词/旁白、声音、连续性、制作备注。台词必须能念出来,画面必须能拍出来。

### 阶段 4 · 分场剧情节拍

把每个场景拆成 2–4 个节拍。每个节拍写:目的、变化、画面、关键台词。节拍之间必须有推进,不能是同一件事换说法。

### 阶段 5 · 分镜表

按 `references/storyboard-standard.md`。总镜头 ≤9;每镜 2–8 秒;一镜只做一个主要动作;一镜只用一个主要运镜。每个镜头写清"开始状态 → 结束状态"。人类不出现脸和身体,最多手部。

### 阶段 6 · Seedance 2.0 提示词

按 `references/seedance-prompt-guide.md`。每镜一条,包含:模式、参考图映射、主体定义、动作、场景、运镜、光线、风格、时长、画幅、负面约束。图生视频不要重复描述参考图里已经有的外貌,只写运动、运镜和保持项。风格锚点必须来自 `references/visual-style.md`(A 全片底色 + B/C 构图变体)。

### 阶段 7 · 交付质检

逐项跑 `references/delivery-checklist.md`。输出:剧本、分镜表、提示词、发布包四块,并列出未通过项。未通过项必须修完才算交付。

## 30 秒首版压缩规则

第一次试做、预算极低或只想验证风格时:

1. 6–7 镜;只保留钩子、处境、转折、落点;删掉铺垫、次要动作、重复观察。
2. 图生视频 ≤2 个;其余静帧 + 剪映运镜。
3. 片尾卡 2–3 秒。
4. 台词每镜最多两句;全片总字数控制在 150 字左右。
5. 先跑最短版本验证角色与风格,再扩到 50–65 秒。

## 硬规则

- **时长**:标准集 50–65 秒;第一次试做或低成本测试可用 **30 秒首版**(28–32 秒,6–7 镜,图生视频 ≤2,片尾卡 2–3 秒);镜头 ≤9;只有关键动作镜头做图生视频,其余静帧 + 运镜。
- **人类**:不出现正脸和身体,最多手部;需要人类存在感时用空镜和声音。
- **角色**:芋仔是四足布偶猫,不穿衣服;固定锚点见 `story-bible.md`。
- **风格**:每条 Seedance 提示词必须带 `visual-style.md` 的风格底色 A,再按镜头选 B(大景)或 C(中近景/特写);9:16 竖屏,画面无文字。
- **电量卡**:片尾固定「辞职第 N 天 / 电量 XX% / 下一站:XX」;只写结果,不解释电量怎么充、怎么减。
- **台词**:第一人称,短句;对生人克制,对熟人话多;不煽情,不讲道理。
- **合规**:发布时勾选 AIGC 标识;不编救助/领养情节。
- **成本**:一集 ≤9 镜;先生成 480p 草稿;单镜重试 ≤3 次。

## 常见借口与正确做法

| 借口 | 现实 |
|---|---|
| 「用户说直接给完整方案」 | 完整方案 = 逐阶段确认后拼起来,不是一次倒完。仍先出阶段 0。 |
| 「这集很简单,不用确认」 | 简单集也要过站;输出可以更短,阶段不能跳过。 |
| 「用户已经确认过类似内容」 | 上一集的确认不覆盖这一集。 |
| 「先把剧本写了,分镜以后补」 | 顺序固定:节拍 → 剧本 → 分场节拍 → 分镜 → 提示词。 |
| 「Seedance 提示词顺手写」 | 只在阶段 6 写。提前写 = 跳过用户对分镜的确认。 |
| 「用户没回复,我先继续」 | 停下等待。没有明确「确认」就不推进。 |
| 「用户说『你定』」 | 可以替用户选,但标 `[我的选择]`,然后仍停在确认点。 |

## 红旗

出现以下任一情况,立刻停下重来:

- 一条消息里出现两个阶段的正式产出
- 没有以「【阶段 N · 等待确认】」收尾
- 自己发明世界观、角色前史或人类主角
- 镜头数超过 9,或总时长超过 65 秒
- 让人类正脸/身体出镜
- 解释电量怎么充、怎么减
- 在分镜确认前写 Seedance 提示词
- 把沉默当成确认
